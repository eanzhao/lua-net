# Lua 5.5 C# 重写路线图

## 目标

本仓库以最新正式版 Lua 为目标，目前对齐的是 Lua 5.5.0。

项目按从头实现的方式推进，整个过程以清晰、分阶段、可验证为原则。

当前仓库的工具链基线是 .NET 10。

长期目标如下：

- 用 C# 重新实现 Lua 5.5，作为学习和理解 Lua 的工程
- 尽量兼容官方 Lua 5.5 编译器能够接受的 Lua 源码
- 按小步、可测试的方式推进
- 每个实现阶段都先在 `docs/` 里补一份文档
- 明确区分版本相关行为，避免把多个 Lua 版本的规则混在一起

## 官方参考

- 最新手册：<https://www.lua.org/manual/5.5/>
- Lua 5.5 说明与变更：<https://www.lua.org/manual/5.5/readme.html>
- 官方测试集：<https://www.lua.org/tests/>
- 官方源码索引：<https://www.lua.org/source/5.5/>
- 本地参考源码：`references/lua-5.5.0/`

我们先追求一个结构清楚、容易验证、便于学习的实现。

## 交付规则

后续每一个实现步骤，都必须在 `docs/` 下新增一份文档。

每份步骤文档至少应包含这些部分：

1. 背景和官方参考
2. 本步骤范围
3. 数据模型或模块设计
4. 实现清单
5. 完成标准
6. 明确延期的内容

建议命名如下：

- `docs/001-roadmap.md`
- `docs/002-step-01-foundation.md`
- `docs/003-step-01-source-reference.md`
- `docs/004-step-02-runtime-model.md`
- `docs/005-step-03-bytecode-loader.md`

## 目标架构

后续实现逐步按下面这个结构展开：

- `src/Lua.Runtime`
  运行时值、栈、调用帧、闭包、表、状态对象
- `src/Lua.Bytecode`
  二进制块读取、写出、指令元数据、反汇编
- `src/Lua.Syntax`
  词法分析、语法分析、AST
- `src/Lua.Compiler`
  AST 到内部原型或字节码的编译
- `src/Lua.StandardLib`
  基础库、`table`、`string`、`math`、`coroutine`、`utf8`、`package`
- `src/Lua.Cli`
  REPL、脚本执行、诊断输出
- `test/Lua.*.Tests`
  单元测试、夹具测试、兼容性测试

不需要第一天就把这些项目全部建出来，但新的代码应该朝这个方向组织。

## 阶段计划

### 第 1 步：基础基线与规范对齐

目标：
把目标版本锁定为 Lua 5.5，并为后续阶段搭好基础。

交付物：

- `docs/` 下的阶段文档
- 更清晰的解决方案结构
- 官方夹具和测试策略
- 本地官方源码参考
- 只面向 Lua 5.5 的兼容性策略

完成标准：

- 仓库文档里明确列出官方参考来源
- 本地保留可查阅的 Lua 5.5 官方源码
- 项目边界基本明确
- 测试策略已经写清楚

### 第 2 步：运行时值模型

目标：
在写 VM 之前，先把核心运行时类型定义清楚。

范围：

- `nil`、布尔、整数、浮点、字符串、表、函数、线程、`userdata` 占位
- 栈槽
- 调用帧
- 运行时状态对象

完成标准：

- 运行时类型可以独立编译
- 单元测试覆盖值行为和基本转换
- 核心类型中不混入控制台输出

### 第 3 步：Lua 5.5 字节码加载与反汇编

目标：
正确读取官方 Lua 5.5 二进制块，并输出结构化结果。

范围：

- 头部解析
- 5.5 的尺寸、整数、字符串解码
- `proto` 读取
- 指令元数据表
- 可读的反汇编输出

完成标准：

- 能读取真实的 Lua 5.5 二进制块
- 能对小型夹具程序做反汇编
- 测试覆盖解析失败场景和 golden 输出

### 第 4 步：VM 骨架

目标：
先让一小部分指令在手工构造的原型上跑起来。

范围：

- 取指、解码、执行循环
- 寄存器模型
- 算术运算
- 比较
- 跳转
- 最小表构造和原始表访问
- 简单返回

完成标准：

- 小型合成程序能正确执行
- VM 状态变化有测试覆盖

### 第 5 步：调用、闭包、上值、可变参数

目标：
让 Lua 函数调用真正工作起来。

范围：

- Lua 闭包
- 上值捕获
- 可变参数处理
- 调用与返回协议
- 在可行范围内处理尾调用

完成标准：

- 嵌套函数可以工作
- 闭包能正确观察捕获到的状态

### 第 6 步：表与元表

目标：
补上 Lua 最核心的数据结构。

范围：

- 表结构
- 数组区和哈希区行为
- 原始访问
- 元表查找
- 运行时执行所需的关键元方法

完成标准：

- 表相关语义有测试覆盖
- 常见元表行为可用

### 第 7 步：标准库基础版

目标：
让真实脚本开始具备可运行性。

范围：

- `_G`、`assert`、`error`、`pcall`、`type`、`tostring`、`tonumber`
- `table`、`string`、`math`、`utf8`
- 基础版 `coroutine`
- 文件和操作系统相关库放到核心稳定之后再做

完成标准：

- 代表性的 Lua 脚本无需额外脚手架即可运行

### 第 8 步：词法与语法分析

目标：
支持直接输入 Lua 源码，而不只是执行字节码。

范围：

- 分词
- AST
- 带源码位置信息的语法错误

完成标准：

- 解析器能处理 Lua 5.5 的核心语法
- 具备解析成功和解析失败的夹具

### 第 9 步：编译器

目标：
把 Lua 源码编译成内部原型或字节码。

范围：

- 作用域解析
- 局部变量和上值
- 表达式降级
- 语句降级
- 常量表和原型生成

完成标准：

- 简单 Lua 源文件可以编译并交给我们的 VM 运行

### 第 10 步：兼容性收口

目标：
把“能跑演示”推进到“能跑真实 Lua 程序”。

范围：

- 接入官方测试集
- 补语言边角行为
- 补标准库差异
- 整理诊断和工具链

完成标准：

- 能汇报官方测试集的通过情况
- 已知缺口有明确文档记录
- 与完整 Lua 5.5 语言兼容之间的差距可以被量化

## 工作原则

- 先保证正确性，再谈性能
- 优先做小的纵向切片，不做一口气的大重写
- 每一步先写文档，再写代码、测试和说明
- 所有版本相关逻辑都要明确标记为 `Lua55`
